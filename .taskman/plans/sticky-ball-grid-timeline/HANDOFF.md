# Контекст

Реализация в React+Konva-редакторе PlaybookBuilder четырёх изменений, одобренных на интерактивном макете (`prototype-sticky-ball.html`):

1. **Липкий мяч** — мяч «прилипает» к игроку-владельцу. Позиция мяча = позиция владельца + смещение (производная, а не свой трек). Передача: перетаскивание мяча на игрока (с подсветкой приёмника синим) или выбор в «Свойствах». Промах → возврат к владельцу. Свободный режим (без владельца) — по своему треку.
2. **Сетка-квадраты** — поле разбито на квадраты (GRID=50), привязка к узлу (пересечение) или центру (шаг 25). Визуальная сетка поверх разметки, видна при вкл. привязке.
3. **Таймлайн длиннее** + кнопки «следующий/предыдущий кадр», счётчик кадров, перетаскиваемый за кружок плейхед, клик по линейке/дорожкам = перемотка.
4. **Мяч под регбийный** — овал со швом вместо круга. Вдобавок — кольцо владельца (зелёное пунктир) и приёмника (синее).

## Модель данных
- `BallData`: добавлены опц. `carrierId?: string|null`, `offsetX?: number`, `offsetY?: number`. Старые файлы грузятся (нет поля → мяч свободен по своему треку, как раньше). Сериализация JSON/YAML сохраняет как есть (без смены schemaVersion).
- `resolvePosition(objects, obj, t, mode)`: для мяча с `carrierId` (существующий игрок) возвращает `carrierPos + offset`; иначе `interpolate(obj.track)`. Единый источник позиции для редактора и экспорта.
- `setBallCarrier(id|null)` в store; `receiverId` — transient UI-стейт (не в истории) для подсветки приёмника.

- `src/export/gifExporter.ts` — позиция мяча через resolvePosition.

## Поведение передачи (соответствует макету)
- Драг мяча с владельцем → бросок на игрока (≤REACH) = передача; промах = возврат к владельцу.
- Драг свободного мяча → бросок на игрока = прикрепление; промах = движение по своему треку.
